# Dr. Data Website ADRs and Lessons

## Aug 1 2026 session

### Architecture decisions
- kimi-app-reserve/ is the live app source of truth. Root index.html and assets/ are BUILD-GENERATED by the sync scripts; never hand-edit them as source. Netlify publish dir is dist/.
- Prerendered-page pattern for any new findable page: add to PAGE_PATHS (sitePaths.ts), add a case in App.tsx, add an entry in PAGE_META (pageMeta.ts), add to sitemap.xml. This produces real HTML at dist/<page>/index.html that crawlers and AI engines can read. Client-only ?page= routes are NOT findable.

### Commit and build discipline
- Two-commit rule after a build: (1) source commit, then (2) a separate "build: sync root" commit for the regenerated root index.html and assets.
- Only git rm an old asset bundle if a NEW hashed bundle actually replaced it. Text or SEO-only changes may not change the JS hash; a blind git rm deletes a still-needed file and breaks the live site. Verify the bundle changed before removing (near-miss occurred and was hotfixed).
- No git add dot; stage files by name. npm run build must exit 0 with zero TypeScript errors before commit.

### Supabase capture pattern
- RLS: anon can INSERT but cannot SELECT. So: generate the id client-side with crypto.randomUUID(), insert WITHOUT .select(), reuse that id for the linked events row. Never .select() as anon.
- Never trap a user deliverable (guide download, quiz result) behind a failed insert. Always deliver; capture is best-effort.
- Env vars VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY are set in Netlify and in local .env.local (gitignored, never commit).

### Content and honesty
- Claim CAPABILITIES freely on product pages. Claim RESULTS only when real and permissioned (case studies and testimonials wait for the Review feature and client permission).
- Never publish secret sauce (the STZ framework and its layers, the discovery questions, engine internals). Buyer-facing pages come from buyer-facing write-ups, never from internal build plans.
- No pricing published on the site.
- No em dashes anywhere in copy; use colons, commas, periods. Copy sounds like the founder: short, plain, punchy, declarative.

### SEO and GEO
- Buyers search pain and tools, not "decision intelligence." Optimize titles, descriptions, and one quotable answer line per page around real search intent.
- Do NOT use "air-gapped" in buyer-facing copy; buyers search "private AI", "private LLM", "HIPAA compliant AI". Keep technical terms (GraphRAG etc.) where they signal expertise, but pair them with plain language.
- The professional-services verticals (legal, CPA, healthcare, insurance, MSP) are the biggest untapped SEO/GEO wedge, captured on the Private Hub page. Do not build per-vertical landing pages until a real client in that vertical is served.
